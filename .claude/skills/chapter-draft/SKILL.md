# 下書きスキル

1話分の下書きを書く。ここで作るのは**下書き**で、仕上げ（文字数の調整・矛盾の直し・NG表現の除去）は `chapter-polish` で行う。ただし、校正で直す量を減らすため、文体ルールとNG表現は書く前に読んで守る。

## 前提

- 本編: `NNN.txt`（3桁連番）、閑話: `閑話NNN.txt`
- 本編は天城 閃の一人称「俺」。閑話は視点が自由（CLAUDE.md）
- 見てよいのは `docs/`（`docs/source/` の写しを含む）と、このプロジェクトの本文だけ。**〈ゲーム〉〈奮闘記〉のフォルダは見ない**
- **ゲームの数値は出さない**（兵の数・HP・技の回数・倍率・ターン）。人数は「30人ほど」のように物語の中の人数として書く
- 1話の目安は2,000〜3,000文字（盛り上がる話は5,000文字ほどまで）

## 手順

### 1. 書く話を決める
- 依頼の話数を `docs/plot_plans.md` の話数の表で探し、概要と元ネタ（`#番号`）を確かめる
- 話数の指定がなければ、`docs/story_knowledge_base.md` の「最終更新」から次の話を選ぶ
- `plot_plans.md` の「書く前に決めること」に、この話にかかる項目が残っていれば、**書く前にユーザーに聞く**（推測で決めて書かない）
- 案と違う筋にしたい点があれば、書く前に提案する

### 2. 読む
- 毎回全文読む: `docs/prose_style.md`・`docs/ng_expressions.md`
- 元ネタ: `docs/source/chNN/story.md` の、この話の `#番号` の範囲（前後の数行も）。物語の文は**筋とセリフの材料**で、そのまま写さない。ゲームの画面の指示（【演出】【背景】【立ち絵】）は使わない
- キャラ: 出てくるキャラを `docs/characters_knowledge_base.md` で確かめる（話し方・呼び方・一人称・会話例）
- 技: 技が出るなら `docs/skills_knowledge_base.md`（見え方・使うときのセリフ・使いどころ）
- 場所・状況: `docs/map_location_notes.md`・`docs/world_knowledge_base.md`（何日目か・食料の残り・空腹）
- 流れ: `docs/story_knowledge_base.md` と、直前2〜3話の本文（口調・前話の終わり方・時間のつながり）
- KB にない細かいことは、写し（`docs/source/chNN/`）を `Grep` で探す。写しにもなければ、推測で書かず、提案として別に挙げる

### 3. 書く
- **具体的なこと（場所・人数・何日目か・だれがどこにいるか）を含む一文は、書く前に KB を確かめてから書く**（書いたあとの見直しだけに頼らない）
- 一人称「俺」: 閃が見ていないこと・知らないことを地の文に書かない。閃の気持ちや理由を地の文で長々と説明しない（`prose_style.md`）
- セリフで見せる。同じ人の動作・表情を、セリフを挟まずに2つ続けない。「〇〇が言った」だけの地の文を毎回付けない
- 場面の切り替えは、空行のあと `＊　＊　＊` の1行、そのあと空行
- 1つの動作や一語だけの短い文を、1行ずつ並べない（短文禁止。読点でつないで1文にする。`prose_style.md`）
- 地の文は1文ごとに改行する。段落の切れ目とセリフの前後は空行（`prose_style.md`「改行の位置」）
- 話の最後は、まとめの一文や予告で締めず、行動かセリフで終える
- 技名は `|技名《ルビ》` の形。質問のセリフには「？」。「？」「！」は全角
- 数・時刻・時間・人数・回数は半角のアラビア数字（8時12分・30人ほど）。一緒・一気などの決まった言い回しは漢数字（`prose_style.md`）
- 前の話と同じ組み立て・同じ決め台詞を使い回さない（`prose_style.md`「場面の組み立てを使い回さない」）

### 4. 確かめる
- 文字数を数える（目で数えない。`(Get-Content -Raw -Encoding UTF8 "path").Length` など）。目安から外れていれば、書き足すか削る
- `ng_expressions.md` の表現が入っていないか、`grep` で照らす
- 数値・ゲームの言葉（兵・HP・ターン・バフ・フェーズ・レベル）が入っていないか照らす

### 5. 出す
- 下書きを `NNN.txt`（閑話は `閑話NNN.txt`）に書き、全文を見せる。**同じ名前のファイルがもうあれば、上書きせずにユーザーに聞く**
- 本文のあとに、次を短く添える
  - タイトルの案（`title.md` にはまだ書かない）
  - 文字数
  - 案（plot_plans.md）から変えたところ
  - 新しい設定の提案（本文に既成事実として書き込んだものがあれば、それも挙げる。採用はユーザーが決める）
- 次は `chapter-polish` で仕上げる、と伝える

## 注意
- ナレッジベースは直さない（確定したら `kb-sync` の担当）
- 写しや KB で決まっていないことを、もっともらしく書き足さない。迷ったら提案として別に挙げる
