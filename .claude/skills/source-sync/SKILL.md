# 元ネタ取り込みスキル

ゲームの資料を、このプロジェクトの `docs/source/` に写す。小説のほかの作業（書く・直す・採点・KB反映）は、この写しとナレッジベースだけを見る。

## 前提

- 〈ゲーム〉の場所は CLAUDE.md の「PCごとのフォルダの場所」。`snap.py` の `GAME_DIRS` にも同じものを書いてある（PCが増えたら両方に足す）
- 写しは2層に分ける
  - **写し**（`docs/source/chNN/*.md`）: ゲームの資料を範囲ごとにそのまま。数値も残す。直さない
  - **ナレッジベース**（`docs/*.md`）: 小説の正。写しから要点を取り、数値を消し、小説で変えたことを書く
- 何を写すかは `docs/source/chNN/manifest.tsv`（出力・元ファイル・題・行の範囲）。写した記録は `docs/source/import_log.md`
- 写す・確かめるのは `snap.py`（このフォルダ）。手で書き写さない（写し間違いを防ぐため）
- mdファイルへの書き込みは、**変更内容を提示し、ユーザーの確認を取ってから**行う（写しの作成は除く。写しはゲームと同じ中身なので、作ってから一覧を見せればよい）

## A. 章を始めるとき（新しい章を写す）

### 1. 写す範囲を決める
- ゲームの元ネタの一覧（CLAUDE.md の「元ネタの場所」）から、その章に要るファイルと範囲を探す。大きいファイル（`story-list.md`・`concept.md`・`ui-design.md` など）は、見出し（`grep -n "^#"`）で章の範囲だけを選ぶ
- 1章の `docs/source/ch01/manifest.tsv` を見本にする。章ごとに、だいたい次をそろえる
  - 物語の文（`data/story-list.md` のその章）・章の流れ（`spec/chapterN-design.md`）・世界の決まり（`spec/concept.md` のその章）
  - キャラ図鑑（`data/characters/*.md` の、その章に出る勢力）・見た目（`prompts/characters/character-visuals.md`・`chapter3-visuals.md`）・話し方（`story/style/voices.md`）
  - 技の中身（`data/chapterN-units.md` など）・技の見た目（`prompts/skill-fx/*.md`）
  - 場所（`data/places.md`・`spec/ui-design.md` のマップ）
  - 3章は勢力と真相（`story/briefs/*.md`）
- 画像の指示書のうち、画像を作るためだけの指定（構図・解像度・ファイル名など）しかない節は写さなくてよい。見た目の言葉（髪・服・色・技の光り方）があるなら写す
- 範囲の案（ファイル・行・理由）をユーザーに見せて、確認を取る

### 2. 写す
- `docs/source/chNN/manifest.tsv` を書き、次を実行する
  ```
  python -I .claude/skills/source-sync/snap.py copy docs/source/chNN
  ```
- 「注意: コミットしていない変更がある」と出たら、ユーザーに伝える（ゲーム側をコミットしてから写すのがよい）
- できた写しの頭と終わりを読み、範囲が見出しの途中で切れていないか確かめる

### 3. ナレッジベースに足す
- 写しを読み、各ナレッジベースに足す案を作る
  - `characters_knowledge_base.md`: その章のキャラ（見た目・性格・話し方・呼び方）。話し方は `voices.md` の会話例を残す
  - `skills_knowledge_base.md`: 技の見た目・使いどころ。**倍率・回数・レベルなどの数値は書かない**
  - `world_knowledge_base.md`: その章の状況の決まり。ゲームの言葉（兵・HP・ターン・フェーズ）は小説の言葉に置き換える
  - `map_location_notes.md`: 場所とつながり
  - `plot_plans.md`: 話数ごとの案（`#番号` で写しの物語の文を指す）。ゲームの分岐（勝ち負け・選択肢・ルート）は1本に決める案を出す
- 元ネタの中で食い違うところ（人数・日数など）は、`plot_plans.md` の「書く前に決めること」に挙げて、ユーザーに聞く
- 各 KB の頭の「元ネタ:」の行に、写しのファイルを書く

### 4. 記録する
- `docs/source/import_log.md` に1行足す（日付・章・ゲームのコミット・したこと・KB に足したこと）

## B. ゲームが変わったとき（写した版との差を確かめる）

### 1. 変わったファイルを探す
```
python -I .claude/skills/source-sync/snap.py check docs/source/chNN
```
- 章ごとに実行する。「変わった」と出たファイルについて、差を見る
  ```
  git -C 〈ゲーム〉 diff <写した版> -- docs/<元ファイル>
  ```
- 差が写した範囲の外だけなら、取り込みは要らない（そう報告する）。行がずれて範囲が変わる場合は、manifest の範囲を直す案を出す

### 2. 差を一覧にして聞く
- 写した範囲にかかる差を、次の3つに分けて一覧にする
  - **取り込むとよいもの**: 誤字の直し、小説がまだ書いていない場面の変更、新しい設定
  - **小説と食い違うもの**: 小説ですでに変えた・書いた所とぶつかる変更。**ナレッジベースと確定した本文を上書きしない**。どうするかを聞く
  - **小説に関係ないもの**: 数値・画面・操作の変更
- どれを取り込むかはユーザーが決める

### 3. 取り込む
- 写しは `snap.py copy` で作り直す（範囲の中を手で直さない）
- 取り込むと決まったものだけ、ナレッジベースに足す・直す（手順 A-3 と同じ）
- `import_log.md` に1行足す

## C. 写しにないことが要るとき

- 書く・直す作業の途中で、写しにない資料が要るとわかったら、ゲームを直接読んで本文に使わない。manifest に行を足して `snap.py copy` で写してから使う
- `import_log.md` に「足した」と1行書く

## 注意

- ゲームの資料に書き戻さない（〈ゲーム〉のファイルは読むだけ）
- 写しは直さない。写しの中の誤りや食い違いは、ナレッジベースか `plot_plans.md` に「小説ではこうする」と書く
- 写しの中にある数値をそのまま本文に出さない（本文の決まり）
