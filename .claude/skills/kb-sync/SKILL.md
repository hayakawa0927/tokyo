# ナレッジベース更新スキル

`docs/` 配下の各ナレッジベースを、確定済み原稿の内容に追いつかせる。

## 前提

- ナレッジベース: `docs/story_knowledge_base.md`（章サマリー＋話数索引）、`docs/characters_knowledge_base.md`、`docs/world_knowledge_base.md`、`docs/skills_knowledge_base.md`、`docs/map_location_notes.md`、`docs/ng_expressions.md`、`docs/prose_style.md`
- mdファイルへの書き込みは**必ず変更内容を提示し、ユーザーの確認を取ってから**行う。Git管理下ではあるが、コミット前の誤った追記を無駄に増やさないため

## 手順

### 1. 未反映範囲の特定
- `docs/story_knowledge_base.md` 末尾の「最終更新：〜収録済み」を読み、最後に反映済みの話数を確認する
- 現在存在する最新の確定原稿（本編NNN.txt／閑話NNN.txt）の話数を確認する
- 両者の差分が更新対象範囲になる（例: 203〜213話）
- ユーザーから直接「NNN話まで反映して」と範囲指定があれば、それを優先する

### 2. 対象原稿の読み込み
- 更新対象範囲の生ファイルのみを読む（全話読み込みはしない）

### 3. 各ナレッジベースの更新内容を作成
- **story_knowledge_base.md**
  - 話数索引テーブルに新しい行を追加（`# | タイトル概要 | キーワード`）
  - 章が継続していれば概要・重要イベント・確立された設定・伏線欄を更新。章が変わっていれば新しい章見出しを追加
  - 末尾の「最終更新」記述を最新話数に更新
- **characters_knowledge_base.md / skills_knowledge_base.md / world_knowledge_base.md / map_location_notes.md**
  - 新しく確定した設定（新キャラ、新スキル名、新しい階級・組織構成、新地名など）があれば、既存ファイルのフォーマット（見出し構造・表組みなど）に合わせて追記する
  - 既存設定と矛盾する記述が見つかった場合は、追記ではなく指摘してユーザーに確認する（勝手に書き換えない）
- **ng_expressions.md**
  - 校正作業（`chapter-polish`スキル）で新たに見つかったAIっぽい不自然な表現があれば追加候補として提示する
- **prose_style.md**
  - 校正作業で気づいた新しい文体方針・言い回しの傾向があれば追記候補として提示する

### 4. 確認と反映
- 各ファイルへの追記・変更内容を提示する
- ユーザーの確認が取れたファイルから順に書き込む

## 注意
- 既存の記述スタイル（箇条書き・表・見出しレベル）を厳密に踏襲すること。フォーマットの独自変更はしない
- 1回の更新で欲張って全ナレッジベースを大改造しない。今回の対象範囲で確定した事実の追記に留める
